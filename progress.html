Roman Catapults — Build Progress

A local progress dashboard for this working session. This file is not tracked by git and exists only on this machine — it is a status board for the team, not part of the game.

Requirements

1.Realistic terrain and catapults planned

Close the stylistic gap between the photographic backdrop plates and the flat procedural terrain/catapult drawn in front of them — richer shading, texture, directional golden-hour light, weathering. All within _draw(), no new asset pipeline.

2.Three lives per player planned

GameState.MAX_LIVES goes from 2 to 3. The banner's pip row and the turn logic already read this constant rather than hardcoding two, so the change is mostly the constant itself plus the tests that assumed two.

3.Terrain can knock a catapult sideways planned

New pure function src/core/knockback.gd: a blast within RADIUS = 160px shoves a catapult sideways, away from the impact, by up to MAX_PUSH = 60px at zero distance, falling off linearly to nothing at the radius edge. Applied to every living catapult caught in range (a burnt wreck at zero lives does not get shoved), via a new Catapult.nudge() method, clamped to the same field bounds repositioning already uses.

4.A too-close blast injures you planned

Already true in the existing code, just unproven: Damage.BLAST_RADIUS (96px) is deliberately wider than Catapult.HIT_RADIUS (36px, the radius that ends a shot's flight as a "direct hit"), so a near miss already costs a life — and the damage loop in Battlefield._on_impact already does not exclude the shooter's own catapult, so standing too close to your own blast already hurts you. The work here is to document that intent in code and add the tests that pin it down, not to invent a second radius.

5.Remove "Fallen" planned

Replaced everywhere with ASHES — short, matches the burnt-wreck ending from requirement 6, and sits at roughly the same width as "FALLEN" in the banner's death label.

6.Fire, smoke, and a burnt wreck planned

Keyed off lives lost against MAX_LIVES, not a literal life count, so it stays correct if the life total ever changes again: 0 lost — pristine. 1 lost — smoke plus small flame licks (this is the "injured" state requirement 6 asks for, and it must show actual flame, not smoke alone). 2 lost (one life from destroyed) — heavier fire and smoke. 0 lives left — burnt wreck: charred, darkened colours, the "FALLEN" label replaced by ASHES.

Designer — requirement 1, and the visual half of requirement 6

Terrain (requirement 1): src/battle/terrain.gd _draw() now layers four wobbling strata bands (up from two — each band jitters by the same deterministic offset on its top and bottom edge, so its thickness holds but it reads as uneven sediment rather than parallel cartoon stripes), soft weathering blotches sunk into the rock, short jagged cracks reaching down from the crust seam, and scattered rubble/debris silhouettes sitting on top of the crust. All of it is deterministic noise keyed off column index (a small Thomas Wang integer hash, Terrain._hash01()), so nothing re-rolls or jitters between redraws — a crater carving a new hole does not make the rubble elsewhere on the field dance. A new Terrain.LIGHT_DIR constant (upper-left toward lower-right, matching the low golden-hour sun in the reference paintings) drives a per-segment rim-light/shadow overlay along the crust edge, grouped into contiguous runs rather than one draw call per column. Every new colour is _rock_color or _crust_color run through lightened() / darkened() / lerp() — nothing is a hardcoded warm tone, so the golden fields stay golden and the Alpine field's cold blue-grey stays cold; verified directly (see below), not assumed.

Catapult (requirement 1): src/battle/catapult.gd gained a working-palette pattern (_p_wood, _p_iron, etc., instance fields recomputed once at the top of _draw() and read by it, _draw_wheel() and _draw_arm()) so the whole machine can be recoloured by one switch instead of every draw call re-deciding its own colour. A local_light vector — the same WORLD_LIGHT direction as the terrain's, unwound through the node's own rotation and scale.x mirror — drives: a warm/shadow half-overlay on the frame, a rim highlight and opposing shadow arc on each wheel centred on the light angle rather than a fixed angle, and a brighter near-leg / darker far-leg on the A-frame. Added wood-grain strokes on the frame planks and the arm shaft, and a chip mark on each wheel rim and corner bracket, for the "worn/chipped iron, visible grain" half of the requirement.

Requirement 6 (visual half): _draw() computes lost := GameState.MAX_LIVES - player.lives and burnt := player.lives <= 0 directly (no new API), and branches burnt first, then lost >= 2, then lost >= 1 — >= rather than ==, and burnt checked on lives <= 0 rather than on a lost-count equal to MAX_LIVES, so both stay correct however many lives a match starts with, and a dead machine can never fall through to the "ablaze" branch. lost == 1 draws a small flame and smoke wisps (not smoke alone, per a literal read of requirement 6). lost == 2 draws two fire sources, a taller flame and thicker smoke — visibly heavier than the first tier. lives == 0 swaps the working palette toward char/rust/soot, draws guttering embers instead of active flame, and droops and desaturates the pennant cloth. Flame, smoke and embers animate off Time.get_ticks_msec(), read directly inside the new _draw_flame() / _draw_smoke() / _draw_embers() helpers, which already run every frame via the existing queue_redraw() in _process() — no change to _process() itself. The banner's "ASHES" swap is developer1's, not touched here.

A correctness point worth QA's attention: the catapult node is both rotated (ground tilt) and mirrored (scale.x, for facing), so a flame drawn "up" in local coordinates would lean with the chassis and even invert on the mirrored facing. Fire/smoke/embers are drawn inside a draw_set_transform() that cancels both: rotation by -rotation * scale.x (plain -rotation only cancels correctly when scale.x == 1; the extra * scale.x is what makes it exact for the mirrored facing too — worked out algebraically from Godot's R(rotation) * diag(scale.x, 1) transform composition, then checked against a forced 0.35 rad tilt on a left-facing machine, see verification below), and scale by Vector2(scale.x, 1.0) (self-cancelling since scale.x is ±1). The result is a plume that stays vertical in world space regardless of slope or facing.

Developer (phase 2) — requirement 3

New file, src/core/knockback.gd: pure and node-free (class_name Knockback extends RefCounted), following src/core/ballistics.gd's pattern exactly. RADIUS := 160.0, MAX_PUSH := 60.0, and static func push_for(distance: float) -> float returns MAX_PUSH * clampf(1.0 - distance / RADIUS, 0.0, 1.0) — full push at zero distance, linear falloff to nothing at the radius edge.

Wiring, Battlefield._on_impact: a new loop runs after the existing crater-carve and the existing damage loop, over every catapult in _catapults whose player.is_alive() is true (a burnt wreck at zero lives is never shoved). For each: distance := where.distance_to(catapult.body_centre()), push := Knockback.push_for(distance); if push > 0.0, direction := signf(catapult.position.x - where.x) (falling back to 1.0 when signf returns exactly zero — an impact directly below or above the catapult), then catapult.nudge(direction * push).

src/battle/catapult.gd: exactly one new method added, func nudge(dx: float) -> void, placed right after commit_position(). It does base_x = clampf(base_x + dx, 70.0, Terrain.WIDTH - 70.0) then position.x = base_x — the same clamp bounds set_step_offset() already uses, so a shove can never push a catapult off the field, and writing base_x (not just position.x) means the shove survives into that catapult's own next turn. Nothing else in the file was touched: _draw(), _draw_wheel(), _draw_arm() and every colour constant are byte-for-byte the designer's phase-1 work — confirmed with git diff -- src/battle/catapult.gd | grep '^+func', which shows only nudge() as a change I introduced against the designer's already-uncommitted additions.

Test, tests/run_tests.gd: a new _test_knockback() checks push_for(0.0) == MAX_PUSH, push_for(RADIUS) == 0.0, push_for(RADIUS * 0.5) == MAX_PUSH * 0.5, and push_for(RADIUS * 2.0) == 0.0.

Flagged for the team lead/orchestrator, not fixed here: a discovered interaction between nudge() and mid-turn repositioning. If the current shooter has already dialled in a nonzero step_offset (so position.x = base_x + step_offset * STEP_PIXELS) and a blast then shoves that same catapult — self-injury from a too-close shot is explicitly by-design per requirement 4 — nudge() writes position.x = base_x, which silently drops the step displacement rather than adding dx on top of it. Reproduced with a throwaway script (written to tools/, deleted after use): a catapult at base_x = 190, stepped to step_offset = 2 (position.x = 242), hit by a blast 40px from its centre (push_for(40.0) = 45, direction = -1) ends up at base_x = position.x = 145 — a 97px on-screen jump, not the 45px the push formula computed, and the two repositioning steps the player just took are discarded outright rather than combined with the shove. step_offset itself is left stale at 2 until _end_turn()'s commit_position() zeroes it. This is exactly the specified formula (base_x = clampf(base_x + dx, 70.0, Terrain.WIDTH - 70.0); position.x = base_x) behaving exactly as dictated — not a bug in this implementation — but whether a self-inflicted knockback should stack on top of an in-progress step offset, or override it, or whether self-knockback should be excluded entirely, is a design call above this ticket's scope. Left unchanged pending that call.

Bugfix pass — QA's blocking issue: self-knockback discarding the step offset

Verdict on the earlier "design call" punt above: QA's second review treated it as a bug, not a design question, and asked for a fix rather than a decision. Resolved as: a knockback shoves from wherever the catapult currently stands, stacking on top of any in-progress reposition rather than overriding it — the option the earlier build-log entry framed as one of three choices, picked because it is the only one where a player's own input is never silently thrown away.

src/battle/catapult.gd nudge(): changed from shoving off base_x (the turn's starting position) to shoving off position.x (wherever the machine actually stands right now, stepped or not), then folding the result into both base_x and step_offset = 0 — the same pair commit_position() already sets, so a shove reads as "the turn's repositioning is now settled here" rather than leaving a step count that no longer matches reality. Three lines changed, nothing else in the file touched.
